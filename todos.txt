[dense GPU 大 tile 性能问题 - 已修复]:
  - 现象: GPU dense alignment 时间随 tile_size² 增长. SLg2 48 帧 (RTX 5060 Ti) v3 实测:
      t=16: 7.13s, t=32: 9.17s, t=48: 10.30s, t=64: 13.55s, t=96: 19.42s, t=128: 29.14s.
    CPU 在同样区间 15.59→17.76s 几乎平 (OpenMP 充分并行, ts² 平摊).
    导致用户案例 `--backend vulkan -a dense -t 96 -m expbkt-avg` (5060 Ti): GPU 19.79s
    vs CPU 15.81s, GPU 反而慢 25%.
  - 根因: dense_level.comp v3 设计为 "每 workgroup(8×8) 处理 64 tile, 每 thread 1 tile,
    内层 ts² px 串行". ts=96 时每 thread 累加 9216 px × 4 candidate × Kahan M=8 累加器,
    8×8=64 float 寄存器占用满 register file, SM occupancy 暴跌.
  - 修复 (dense_level.comp v4, 2026-07-04): 64-thread-per-tile 协同设计 — 每个 workgroup
    (8×8) 协同处理 1 个 tile (而非 64 个 tile), thread tid 处理 tile 内 stride-64 的
    1/64 像素 (而非全集 9216 px), 共享 shared memory (4*64 float = 1KB) 做 64-thread
    partial cost 的 pairwise tree-reduction. dispatch 维度变 (tiles_x, tiles_y, 1)
    替代 v3 的 (ceil(tiles_x/8), ceil(tiles_y/8)). ts² scaling 完全消除, 测试结果:
      t=16: 6.7s, t=32: 6.7s, t=48: 6.8s, t=64: 6.5s, t=96: 7.4s, t=128: 7.4s.
    用户案例 GPU 现 8.09s vs CPU 16.27s, GPU 快 2.0×.
  - 一致性回归: LongUnder2 dense t=96 包围曝光 + 高光恢复, CPU vs GPU v4 MAD 0.022,
    16-bit 量级单 LSB 抖动 (与 v3 旧路径 MAD ~0.016% 量级一致, 没有发散放大).
  - 遗留: dense_level_fp64.comp 仍是 v3 形状 (1-thread-per-tile), 待后续也做 v4 重写.
    AGENTS.md "GPU 已知性能陷阱" 段同步更新.

[已完成] 包围曝光平均 (ExpBracketAverage):
  - 新合并模式 MergeAlgorithm::ExpBracketAverage (CLI alias exp-bkt-average / expbkt-avg).
  - 算法: EV 权数 wn=1/scale + max-across-channels 硬裁切门 (同 spatial clip gate).
    参考 frame 始终 weight 1; 无 BoxBlur (比 TemporalAverage 更快, CPU ~5-7%).

  - CPU: temporal.cpp::ExpBracketAverage + ExpBracketAverageParams (denoise/temporal.h).
    GPU: expbkt_acc.comp (pc.f0=clip_scaled, pc.f1=scale) + normalize_div 收尾.
    分发: pipeline.cpp (RAW+RGB), gpu_pipeline.cpp GpuPipelineCore.
  - CPU/GPU 一致性: 等曝光 MAD 0.016 (rel 0.001%); 包围曝光 MAD 0.044 (rel 0.004%),
    但硬裁切门在高光边界处 CPU/GPU warp 微差可导致二值翻转 (Bkt1 2% 像素差异, 集中在高光区域).
  - 性能: vs TemporalAverage — CPU 快 5-7% (无 BoxBlur); GPU 基本持平.
